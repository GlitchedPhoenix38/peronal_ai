# WORKFLOW.md

Before making any changes:

1. Read INSTRUCTIONS.md completely.
2. Analyze the existing project.
3. Understand the architecture.
4. Identify all relevant files.
5. Explain your plan before modifying code.

## Safety Rules

Do NOT:

* Rewrite the entire project.
* Change APIs.
* Change database schemas.
* Change authentication.
* Change environment variables.
* Remove features.
* Delete files unless explicitly approved.
* Replace frameworks.
* Change package managers.
* Refactor unrelated code.

## Required Process

Phase 1:

* Audit current implementation.
* Identify problems.
* Explain proposed improvements.

Phase 2:

* Wait for approval.

Phase 3:

* Implement changes incrementally.
* Keep commits small and focused.

Phase 4:

* Verify:

  * No functionality broken.
  * No TypeScript errors.
  * No build errors.
  * No responsiveness regressions.

## Redesign Rules

When redesigning:

Preserve:

* Existing functionality
* Business logic
* Data flow
* User flows
* APIs

Improve only:

* Visual design
* Layout
* Typography
* Spacing
* Responsiveness
* Accessibility
* Component consistency

## Before Finishing

Provide:

1. Summary of changes.
2. Files modified.
3. Risks introduced.
4. Remaining improvements.
5. Testing recommendations.
